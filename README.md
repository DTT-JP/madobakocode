# MadoBakoCode

ブラウザだけで HTML / CSS / JS（と画像・動画・音声）を書いて実行できる、バックエンド不要のエディター兼プレビューアプリです。
ファイルは端末内の IndexedDB に保存され、再訪時に前回の状態へ戻ります。

## 仕組み（概要）

- プレビューは Service Worker（`sw.js`）が `__preview__/` 配下のリクエストを IndexedDB から返し、iframe で表示します。相対パス、`fetch('data.json')`、ES Modules、動画のシーク（Range）がそのまま動きます。
- 相対パスのみ対応です（`/` 始まりの絶対パスは非対応）。外部 CDN の読み込みは可能です。
- プレビュー中の `console.*` / エラー / 読み込み失敗は、下部のコンソール（⌨）にファイル名・行番号つきで表示されます。
- 書き出し・取り込みは ZIP のみです。

## ファイル構成

```
madobakocode/
├─ index.html              アプリ本体の HTML
├─ vite.config.js          base: './'（サブディレクトリ配信対応）
├─ package.json
├─ public/
│  ├─ sw.js                Service Worker（プレビュー配信 + アプリのオフライン起動）
│  ├─ manifest.webmanifest PWA 設定
│  ├─ icon.svg             アイコン原本（窓から箱入りコードをのぞく図）
│  ├─ apple-touch-icon.png iOS ホーム画面用（180x180）
│  └─ icon-192.png / icon-512.png / icon-maskable-512.png  PWA 用 PNG
└─ src/
   ├─ main.ts              アプリ本体（UI・保存・エディター・ZIP）
   └─ style.css
```

## データの保存について

ファイルはブラウザの IndexedDB に保存されます。保存まわりは次の方針で作っています。

- **書き込みは順番に1つずつ、1操作＝1回で確定**します。名前変更・移動・削除・ZIP読み込み・リセットは、途中でページを閉じても「半分だけ反映」にならず、全部反映されるか全部されないかのどちらかです。
- 保存に失敗したときは、接続を開き直して1回だけ再試行します。それでも失敗したら、ダイアログでお知らせします（ZIPで書き出してバックアップしてください）。
- **編集中のテキストは、IndexedDB に確定するまで `localStorage` にも控え**を残します。ページを閉じる瞬間に保存が間に合わなかった場合は、次に開いたときに自動で復元し、ダイアログでお知らせします。
- 画像などのバイナリは、WebKit（Safari）のプライベートブラウズでも保存できる `ArrayBuffer` で保持します。旧バージョンが Blob で保存した分は、起動時に自動で移行します。
- IndexedDB が使えない環境では、メモリ上だけで動作し、起動時にその旨を表示します（ページを閉じると内容が消えます）。

### プライベートブラウズなど、保存が一時的になる環境

Safari のプライベートブラウズなどでは、ブラウザの仕様として、タブやウィンドウを閉じるとサイトのデータが消える場合があります（ブラウザ側の仕様のため、アプリ側では防げません。挙動はバージョンにより異なるため **要確認**）。

このアプリは、起動時に「IndexedDB に Blob を保存できるか」を試し、保存できない環境（プライベートブラウズなどの可能性が高い）では、その旨を最初に1回表示します。そうした環境では、**作業のあとに必ず `ZIPを書き出す` でバックアップ**してください。また、対応しているブラウザ（主に PC）では、書き出していない変更がある状態でページを閉じようとすると確認が出ます（iPhone / iPad の Safari では出ません）。

## 画面サイズ別の表示（モバイル最適化）

画面の向きと幅で、表示が3種類に切り替わります（切り替えは自動。向きを変えると即座に変わります）。

| 画面 | 条件 | 表示 |
| --- | --- | --- |
| PC・横向き | 横長の画面 | 従来どおり（左メニュー + ファイル一覧 + 本体）。幅 880px 未満は横スクロール |
| タブレット縦向き | 縦長 かつ 幅 600px 以上 | 左メニューを **アイコンだけ** に縮小（初期状態）。左上の **ロゴをタップ** すると文字つきの通常表示に戻り、もう一度タップするとアイコンだけに戻ります。アイコンだけのときコード・ファイル・プレビューが広くなります。この状態は端末に保存されます |
| スマホ縦向き | 縦長 かつ 幅 600px 未満 | 下記の専用レイアウト |

### スマホ縦向きのレイアウト

- 一番上: 左にロゴ、その右に小さくバージョン。右端に ZIP読み込み / ZIP書き出し / リセット（アイコンのみ）。
- 一番下: `プレビュー` `エディター` `ファイル` の切り替えボタン。
- 切り替えボタンのすぐ上に、操作ボタン列（アイコンのみ。内容は下記）。
  - `エディター` / `ファイル`: 削除、すべて選択、すべて選択解除、切り取り、コピー、貼り付け（※ 並び順は従来のメニューと同じです）。
  - `プレビュー`: 再読み込み、コンソール、全画面、読み込む（→）。
- `ファイル`: 上下のボタン以外の全領域に、`FILES (サイズ)`・4つのボタン・スクロールできるファイル一覧を表示します。ファイルをタップすると自動でエディターに切り替わります（複数選択中は切り替わりません）。
- `エディター`: 上にパスとサイズ、その下にコードを表示します。操作ボタン列（切り取り・コピー・貼り付けなど）は、エディターを開いているときはコードの文字に対して働きます。
- `プレビュー`: 操作ボタン列のすぐ上にパス入力欄（Enter でも読み込めます）を表示します。コンソールを開くとプレビューの下に出ます。
- `プレビュー`（全画面）: パス入力欄だけを一番下に残し、ほかはすべて隠してプレビューを全面に表示します。パス入力欄の右端のボタンで全画面を終了します。
- ソフトキーボードを出したとき、下のボタン列がキーボードの上に残るよう、表示領域の高さに合わせます（iOS Safari では **実機での動作確認が必要** です）。
- iOS Safari は 16px 未満の入力欄にフォーカスすると画面が拡大されるため、スマホ表示では入力欄とコードの文字サイズを 16px にしています。

スマホの横向きは対象外で、PC と同じ表示（幅 880px 未満は横スクロール）です。

## アイコンについて

`public/icon.svg` が原本です。iOS（ホーム画面に追加）は SVG を使えないため、PNG を別に用意し、`index.html` の `apple-touch-icon` と `manifest.webmanifest` から参照しています。
デザインを変える場合は SVG を編集し、PNG（180 / 192 / 512px）を書き出し直してください。PNG 側は角丸なしの全面塗りです（iOS が角丸を適用します）。

## 必要な環境

- Node.js 18 以上（ビルド時のみ。動作確認していません）
- 実行側のブラウザ: Service Worker と IndexedDB が使えるもの（Safari / Chrome / Firefox / Edge）。
  HTTPS、または `localhost` で配信してください。

## ビルド

```
npm install
npm run build
```

## ビルド後に何ができるか

`dist/` フォルダが生成されます。中身はすべて静的ファイルで、`sw.js` と `manifest.webmanifest` も含まれます。
`dist/` を任意の静的ホスティング（HTTPS）に置けば、そのまま動作します。サーバー側の処理は不要です。

ローカル確認は `npm run preview`（`localhost` では HTTPS 不要）で行えます。

初回アクセス後はアプリ本体がキャッシュされ、オフラインでも開けます（ユーザーのファイルは常に端末内の IndexedDB にあります）。

## 使い方メモ

- 選択: PC は Ctrl/Shift+クリック、スマホは行の長押し（動かさず離す）で複数選択になり、チェックボックスが出ます。フォルダ行を普通にタップすると、そのフォルダだけが選択状態になります（エディターには表示されません）。フォルダの開閉は行の右端の矢印です。
- 移動: ファイル・フォルダの行のどこでもドラッグできます（スマホは長押ししてからドラッグ）。掴んでいる種類アイコンとファイル名が表示され、移動先は枠線で示されます。フォルダ行や、その中の行へドロップするとそのフォルダへ、ルートの行や空白へドロップするとルートへ移動します。
- ファイル一覧の上のボタン: `コードを追加`（HTML / CSS / JS のボタンか、自由入力。使える拡張子は html htm css js mjs wasm json csv tsv txt md xml、大文字小文字は問いません）、`フォルダを追加`、`ファイルを追加`（画像・動画・音声などのアップロード）、`名前を変更`。
- 削除: 削除前に、コード・ファイル・フォルダの名前と個数（フォルダの中身は別カウント）を確認ダイアログに表示します。エディターで範囲選択して Delete のときは、一部／全てのテキストの削除を確認します。
- `Del` `^A` `^X` `^C` `^V`: エディターにフォーカスがあればテキスト操作、ファイル一覧にフォーカスがあればファイル操作です。
- プレビューのコンソール（⌨）: エラー・警告・ログがどのファイルの何行目かと一緒に出ます。同じ内容が連続したときは1行にまとめて回数を表示します。ファイル名をタップするとそのファイルの該当行を開きます。
- 全画面: プレビュー上部のバー右端の ⛶。バーは左端が再読み込み、右端が全画面終了です。バーを上へ動かすと隠れ、ページの上端から下へ引くと再び出ます。
- 左下の `Rst` は全削除して初期状態へ、`Imp` は ZIP 取り込み（全置換）、`Exp` は ZIP 書き出しです。バージョンは `Rst` の下に表示されます。スマホ縦向きでは、これらは画面上部右端のアイコンになり、バージョンはロゴの右に表示されます。

## ソースコードのアップロード方法（GitHub へ push）

このリポジトリは、ビルド結果の `dist/` もコミットする運用です（`dist/` は `.gitignore` に入っていません）。ソースを変更したら、ビルドしてから `dist/` ごとコミットしてください。

```
npm install
npm run build
git add -A
git commit -m "変更内容のメモ"
git push
```

- 初めて push する端末では、GitHub の認証が必要です（HTTPS の場合は Personal access token など。手順は GitHub 側の画面が変わることがあるため、公式ドキュメントで最新を確認してください）。
- `npm install` を実行すると `package-lock.json` が書き換わることがあります。意図しない変更なら `git checkout package-lock.json` で戻してからコミットしてください。

### 公開（デプロイ）について

`dist/` の中身を、HTTPS で配信できる静的ホスティングに置けば動作します。

- GitHub Pages のブランチ公開では、公開元に選べるフォルダは **リポジトリのルート `/` か `/docs`** のみです（GitHub 公式ドキュメントで確認）。`dist/` をそのまま公開元には選べないため、`dist/` を公開する場合は GitHub Actions を使うか、`dist/` の中身を `docs/` にコピーするなどの工夫が必要です。現在どの方法で公開しているかは、このリポジトリからは分からないため **要確認** です。
- 設定画面は、リポジトリの `Settings` → `Pages` にあります（表示名は変更されることがあるため、実際の画面で確認してください）。
- Service Worker を使うため、公開先は HTTPS（または `localhost`）が必要です。更新後は、端末にキャッシュが残っていると古い画面が出ることがあります。その場合は、ページを開き直す（またはリロードを2回行う）と新しいバージョンになります。バージョン表記で確認できます。

## 制限事項

- Safari はサイトを一定期間使わないと保存データを消すことがあります。ホーム画面への追加や ZIP バックアップを推奨します（仕様は要確認）。
- JS の `fetch` による外部サイトへのアクセスは、相手側の CORS 設定に依存します。
- `コードを追加` で作成できるのは html htm css js mjs wasm json csv tsv txt md xml のみです（wasm は空のファイルとして作られます）。画像・動画・音声などは `ファイルを追加` で追加します。
